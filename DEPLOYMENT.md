# BuddyBot Deployment

BuddyBot has two services:

- Rasa API: public webhook used by the website.
- Action server: private service called by Rasa for custom answers, SQL, and policies.

## Railway / Render Services

Create two services from this repository:

1. Actions service
   - Dockerfile: `Dockerfile.actions`
   - Port env var: `PORT=5055`
   - Public domain example: `https://buddybot-actions-production.up.railway.app`

2. Rasa service
   - Dockerfile: `Dockerfile`
   - Port env var: `PORT=5005`
   - Env var: `ACTION_ENDPOINT_URL=https://YOUR-ACTIONS-DOMAIN/webhook`
   - Env var: `RASA_TELEMETRY_ENABLED=false`
   - Runtime version: `rasa/rasa:3.6.21` to match the trained model.
   - Public domain example: `https://buddybot-rasa-production.up.railway.app`

The Rasa container generates its runtime endpoint config from `ACTION_ENDPOINT_URL`,
so local `endpoints.yml` can stay pointed at `localhost` for development.

## Website URL

In `SAMS_Enhanced (1).html`, update:

```js
const PRODUCTION_RASA_URL =
  "https://buddybot-rasa-production.up.railway.app/webhooks/rest/webhook";
```

Replace the example domain with the real Railway or Render Rasa domain.

## Local Docker Test

```powershell
cd C:\dev\rasa_project
docker compose up --build
```

Then test:

```powershell
Invoke-RestMethod `
  -Uri "http://127.0.0.1:5005/webhooks/rest/webhook" `
  -Method Post `
  -ContentType "application/json" `
  -Body '{"sender":"test","message":"hi"}'
```

## Database Note

The current actions code can still use local SQL Server through
`BUDDYBOT_DB_DIALECT=sqlserver` and `BUDDYBOT_DB_SERVER`.

For a public cloud deployment, the recommended path is Supabase/PostgreSQL:

```env
BUDDYBOT_DB_DIALECT=postgres
BUDDYBOT_DATABASE_URL=postgresql://postgres:YOUR_PASSWORD@db.xxxx.supabase.co:5432/postgres
DB_SSLMODE=require
```

or the separate fields:

```env
DB_HOST=db.xxxx.supabase.co
DB_NAME=postgres
DB_USER=postgres
DB_PASSWORD=YOUR_PASSWORD
DB_PORT=5432
DB_SSLMODE=require
```

SQL Server exports usually need light conversion before they can run in
Supabase. Keep the FCI views/table names used by BuddyBot, especially
`v_rasa_students`, `v_rasa_gpa`, `v_rasa_schedules`, `v_rasa_rooms`, and
course/instructor views if your deployment uses them.

The action server includes a small compatibility layer for common SQL Server
syntax generated by BuddyBot, such as `SELECT TOP N`, but the database schema
itself still needs to be migrated cleanly.
